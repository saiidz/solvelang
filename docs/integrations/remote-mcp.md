# SolveLang remote MCP boundary

SolveLang includes a repository-safe remote MCP server boundary for clients that cannot launch the local stdio package, including server-side Claude MCP connectors.

This document describes code capability only. It does not claim that a public endpoint is deployed, that a production bearer credential exists, or that any third-party marketplace listing has been submitted or approved.

## Authority model

Remote mode is deliberately narrower than local stdio mode.

It accepts only raw JSON supplied in the MCP request and exposes deterministic read-only analysis. It does not accept workspace paths, read the filesystem, invoke `solvec`, spawn subprocesses, mutate repositories, inspect credential values, or make provider/network calls from tools.

The remote tool set is limited to:

- `solvelang_analyze_n8n`
- `solvelang_generate_n8n_report`
- `solvelang_graph_find_nodes`
- `solvelang_graph_search_nodes`
- `solvelang_graph_dependencies`
- `solvelang_graph_dependents`
- `solvelang_graph_shortest_path`
- `solvelang_graph_impact`
- `solvelang_graph_explain_impact`
- `solvelang_capabilities`

`.solve` validation remains local-only because it requires the local `solvec` executable.

## Transport and authentication

The server uses MCP Streamable HTTP in stateless mode.

- MCP endpoint: `/mcp` by default.
- Health endpoint: `GET /healthz`.
- MCP requests: `POST` only.
- Authentication: bearer-protected by default; an explicit `SOLVELANG_REMOTE_AUTH_MODE=noauth` mode exists for public, read-only plugin deployment.
- Request content type: `application/json`.
- Request ceiling: 4 MiB before MCP parsing.
- Rate limiting: a built-in fixed-window limiter (default 60 requests per 60 seconds per source address) is enforced in the HTTP handler before authentication and before MCP parsing, answering `429` with `Retry-After` once exhausted. It is configurable via `SOLVELANG_REMOTE_RATE_LIMIT` / `SOLVELANG_REMOTE_RATE_WINDOW_MS` (0 disables; invalid values fail closed at startup) and the effective limit is reported by `solvelang_capabilities`. The limiter key is the socket source address as seen by the process, so behind a shared proxy it aggregates callers — edge rate limiting remains required in production.
- N8n/Solve Graph input ceilings remain the existing 2 MiB analysis limits.
- HTTP responses use `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.
- Raw workflow/graph input is not intentionally logged or persisted by the application.

The application token must be 32–1024 UTF-8 bytes with no whitespace/control characters. Bearer-protected deployments should inject it through an approved secret store; never put it in Git, plugin manifests, documentation, or chat.

A deployment may additionally set `MCP_REMOTE_TEST_TOKEN` to a second, independent bearer token intended for third-party directory health checkers (for example Glama). It authenticates the same read-only surface under the same token bounds, is accepted only when set (an unset or empty value disables it), and is revocable on its own — unset it and restart — without rotating the primary token.

For the OpenAI public Plugins Directory, SolveLang's current remote tools do not read private account data and do not perform writes. The intended directory deployment therefore uses explicit anonymous mode plus edge rate limiting and abuse controls rather than a custom API-key scheme. If future tools access private data or take user actions, migrate those tools to MCP OAuth 2.1 instead of reusing the static bearer mode.

The server can also expose OpenAI's domain-verification challenge at `/.well-known/openai-apps-challenge`. Set `SOLVELANG_OPENAI_APPS_CHALLENGE_TOKEN` to the exact token generated by the OpenAI submission portal; when unset, the route remains unavailable.

## Local qualification run

After building the package:

```bash
cd packages/mcp-server
npm ci
npm test
npm run test:packed
```

Run the remote boundary locally with a development-only token:

```bash
SOLVELANG_REMOTE_BEARER_TOKEN='replace-with-a-long-random-development-token' \
SOLVELANG_REMOTE_HOST=127.0.0.1 \
SOLVELANG_REMOTE_PORT=8787 \
npm run start:remote
```

Then the MCP URL is `http://127.0.0.1:8787/mcp` and the health URL is `http://127.0.0.1:8787/healthz`.

To exercise the anonymous public-plugin mode locally:

```bash
SOLVELANG_REMOTE_AUTH_MODE=noauth \\
SOLVELANG_REMOTE_HOST=127.0.0.1 \\
SOLVELANG_REMOTE_PORT=8787 \\
npm run start:remote
```

A production container build is available at `packages/mcp-server/Dockerfile.remote`. Build it with `packages/mcp-server` as the Docker build context. A reviewed production deployment shape (localhost-bound container behind a TLS reverse proxy, host-held env file, hardened container flags) is checked in at `packages/mcp-server/deploy/`. The endpoint's behavior is pinned by protocol-level tests plus a real-client proof (an MCP SDK client completing a context-pack-driven impact task against the locally running server) in `packages/mcp-server/test/remote.test.ts` and `packages/mcp-server/test/remote-client-proof.test.ts`.

**Deployment state (Phase 5, 2026-11-20): LIVE.** The endpoint serves at `https://mcp.solve-lang.com`, deployed 2026-11-20 from main `65909773` as a container on the production host behind TLS (Let's Encrypt), on the owner's explicit production approval. Bearer authentication is required (the production token is held on the host only); the surface is the 10 read-only remote tools; the built-in rate limit is 60 requests per 60 seconds per source and the request ceiling is 4 MiB. Verify at any time: `GET https://mcp.solve-lang.com/healthz` returns `{"status":"ok","service":"solvelang-mcp","mode":"remote-read-only"}`. Still outstanding as production hardening: edge rate limiting in front of the origin (the built-in limiter aggregates behind a shared proxy) and monitoring.

The packaged executable is also named `solvelang-mcp-remote`.

## Public hosting requirements

Before connecting Claude's server-side MCP connector or any internet client, a separate deployment must provide:

1. HTTPS termination with a stable public hostname.
2. Production secret storage and rotation for the bearer credential, or a separately reviewed OAuth upgrade.
3. Network/firewall policy that exposes only the intended HTTPS ingress.
4. Rate limiting and abuse monitoring at the edge/runtime (the runtime limiter ships built in; edge limiting and monitoring are still required).
5. Request/response logging configured so raw JSON and Authorization headers are not retained.
6. Retention/deletion policy and incident-response ownership.
7. Health/availability monitoring and rollback/disable controls.
8. Explicit owner approval for the exact deployment and credential activation.

A repository merge does not satisfy those requirements and does not authorize deployment.

## Claude and Codex relationship

The canonical `plugins/solvelang/` bundle remains the preferred local integration for Codex and Claude Code because it can use the richer local stdio tool set under workspace bounds.

The remote boundary exists for server-side/cloud clients that require a public HTTP MCP server. Once a protected HTTPS deployment is separately approved and verified, its URL can be configured in compatible clients without changing the underlying read-only analysis contracts.
