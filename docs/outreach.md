# SolveLang Outreach Playbook

## Goal

The goal is to start useful conversations with founders, operators, agencies, consultants, and small teams who are losing time to manual workflow routing.

This is not a pitch for a giant SaaS platform. The first offer is simple: ask for one messy workflow, map it clearly, and offer a workflow audit that can turn the process into a readable SolveLang-style workflow.

The main call to action is:

- Send the workflow details to `hello@solve-lang.com`
- Use the intake checklist at https://www.solve-lang.com/audit/

## Who to message

Good-fit prospects are people who already feel the pain of manual routing, follow-up, intake, or reporting.

- Founders posting about being overwhelmed by operations
- Solo operators handling support, sales, onboarding, or reporting manually
- Small agencies handling client intake manually
- Support-heavy SaaS founders who still route tickets by hand
- Consultants managing leads, requests, and follow-ups manually
- Startup operators using spreadsheets, Slack, Gmail, Notion, Airtable, Linear, HubSpot, or similar tools
- People complaining about repetitive workflows, messy handoffs, or too many tools
- Teams where one person still knows "how the process works" because the rules are not written down

## What pain signals to look for

Look for public posts, comments, newsletters, job posts, or founder updates that mention:

- "too many manual follow-ups"
- "inbox chaos"
- "leads falling through cracks"
- "support tickets take too long"
- "we use too many tools"
- "we need better routing"
- "I keep copying data between tools"
- "our ops process is messy"
- "I need a better way to triage requests"
- "everything is in Slack threads"
- "we need to turn emails into tasks"
- "weekly reporting takes too long"

The strongest signal is a specific workflow complaint, not a broad statement like "we need automation."

## Short DM template

Use this for LinkedIn, X, community messages, or warm intros. Keep it short and adjust the first line to the actual pain signal.

```text
Saw your note about [manual workflow / inbox chaos / routing problem].

I'm working on SolveLang, a readable way to map AI-assisted business workflows for founders/operators.

If useful, send one messy workflow here:
https://www.solve-lang.com/audit/

I'll help map what starts it, what decisions happen manually, and what the next automated step could be.
```

## Email template

Subject options:

- Quick workflow audit?
- Can I map one messy workflow for you?
- Saw your ops workflow problem

Email body:

```text
Hi [Name],

Saw your note about [specific workflow pain].

I'm working on SolveLang, a readable scripting language for AI-assisted business workflows. Right now, the useful offer is a small workflow audit, not a big platform rollout.

If you send one messy process, I can map:
- what starts it
- what decisions happen manually
- what output should happen next
- where a readable SolveLang-style workflow could fit

The intake checklist is here:
https://www.solve-lang.com/audit/

Worth sending one workflow over?

Best,
[Your name]
```

## Follow-up template

Send one polite follow-up after 3-5 days. Do not create fake urgency.

```text
Hi [Name],

Quick follow-up on this.

If you have one workflow that keeps turning into manual routing, copying between tools, or missed follow-ups, send the rough version here:
https://www.solve-lang.com/audit/

No need for a polished spec. A messy description is enough to map the next step.
```

## Interested reply template

Use this when someone replies yes, asks how it works, or wants to send details.

```text
Great. Send the workflow details to hello@solve-lang.com.

The easiest format is the checklist here:
https://www.solve-lang.com/audit/

The most useful details are:
- What starts the workflow?
- What tools are involved?
- What decisions happen manually today?
- What should happen automatically?
- What output would make this successful?

Rough notes are fine. The goal is to map the process before talking about implementation.
```

## Qualification questions

Use these questions once someone is interested. Keep the conversation focused on one workflow.

1. What starts the workflow?
2. What tools are involved?
3. Who makes the decision today?
4. What output should happen?
5. What would make this successful?

Useful follow-up prompts:

- How often does this happen?
- What breaks when it is handled manually?
- Which step is most annoying or risky?
- Who needs to review or approve the output?
- Is this a support, sales, intake, reporting, or internal ops workflow?

## First paid offer

Keep the first paid offer fixed-scope and easy to understand.

Suggested offer:

- Map one workflow from trigger to output
- Write a plain-English workflow map
- Draft a readable SolveLang-style workflow
- Outline the automation path
- List the tools or integrations needed
- Recommend the simplest next setup step
- Include an optional custom implementation quote if the workflow is a fit

Position it as a practical workflow audit and setup recommendation. Do not promise full production automation, hosted execution, or deep integrations before the workflow has been mapped.

## Outreach rules

- Personalize the first line around a real pain signal.
- Keep the message short.
- Ask for one workflow, not a meeting.
- Link to https://www.solve-lang.com/audit/ when the person needs structure.
- Use `hello@solve-lang.com` as the lead-capture email.
- Do not use fake urgency.
- Do not overpromise production automation.
- Do not pitch checkout, SaaS plans, or integrations before understanding the workflow.
- Stop after one follow-up unless there is a clear reason to continue.
