# PostHog error sanitizer

`sanitizePostHogErrors` is a pure, single-page transformation for the `read-errors` pipeline injection point. It emits issue UUID, first-seen timestamp, a fixed summary and a recognized status. Names, descriptions, severity text, assignments, external references and cohorts are excluded wholesale. Unknown fields, raw request/response or identity fields outside the reviewed serializer, malformed timestamps/IDs, accessors and more than 100 records fail with a fixed error that contains no provider values or field names.

The reviewed upstream route is `GET /api/projects/{project}/error_tracking/issues/`. Source inspection on 2026-09-05 used PostHog commit `7a2c6545d6218e20ffd63b208a79a963fdaf2183`, specifically `products/error_tracking/backend/presentation/views/issues.py` (`ErrorTrackingIssueReadSerializer`) and `products/error_tracking/backend/presentation/pagination.py`. The response uses `{count,next,previous,results}`. Fixtures are synthetic; no customer data or provider credentials were used.

Coverage means coverage of the returned issue collection, not complete error events, stacks or incident diagnosis. Partial first pages preserve `count - results.length` as skipped records. Links are never followed or returned. Non-first pages fail: current SolveLang request planning models a cursor, whereas this upstream endpoint uses limit/offset. Live pagination/path qualification and owner-approved provider activation remain separate blockers. Null first-seen timestamps and unknown legacy statuses fail instead of inventing evidence.

This helper is not a live connector and is not automatically installed as the default pipeline sanitizer. It adds no provider/network/write authority or retention. Existing transport byte/time limits remain required before accepting any provider response.
