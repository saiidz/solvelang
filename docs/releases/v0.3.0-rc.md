# SolveLang MCP Server v0.3.0 release candidate

_Status: selected candidate line; repository qualification is pending exact-head CI. Not tagged, not released, not published to npm, and not yet the canonical public plugin version._

## Candidate intent

v0.3.0 is the selected next MCP package line for the substantial post-v0.2.0 repository work now present on `main`, including Solve Graph and Solve Context capabilities through PR #924.

The currently published package and canonical Codex/Claude plugin remain `@solvelang/mcp-server@0.2.0` until a separately authorized release finalization and publication actually succeeds. Selecting this candidate does not authorize a GitHub Release, npm publication, marketplace publication, provider calls, production mutation, billing, or customer-source execution.

## Candidate capabilities from current source

Compared with the historical v0.2.0 package line, current repository source includes:

- deterministic Solve Context planning, packing, exact retrieval, source/excerpt SHA-256 provenance, content-addressed handles, and stale-source rejection;
- Claude ↔ Codex context handoff creation and freshness validation;
- correctness-first structured JSON/log/diff compaction with exact expansion where supported;
- changed-path priority plus bounded supplied-Solve-Graph dependency/dependent/test evidence;
- expanded deterministic Solve Graph search, impact, path, cycle, hotspot, entrypoint, security-summary, and affected-validation surfaces;
- pinned first-party and independent external-source Solve Context regressions;
- the strict offline baseline-vs-context agent-evaluation record/report contract and pair-comparability gates;
- the larger Axios and Preact evaluation corpora through #923;
- the #924 precommitted held-out evaluation protocol with answer-key commitment, deterministic selection transcript, post-selection receipt, tamper rejection, and fail-closed claim boundaries;
- locked MCP dependency security checks and packed-consumer/plugin roundtrip qualification.

## Evidence boundary

Repository CI can prove deterministic behavior, package integrity, pinned-source regression results, held-out protocol mechanics, and plugin/package installation boundaries. It cannot prove facts that require an independent evaluator or real model-provider execution.

Therefore this candidate must **not** be described as having already established:

- a genuinely blinded benchmark result;
- provider-reported token savings;
- Claude or Codex task-quality superiority;
- production latency improvement;
- a public comparative advantage over another context product.

Those claims remain gated by issue #898's real-evidence matrix and separate publication review.

## Current evaluation truth

As of the source baseline selected for this release-candidate track, the visible-annotation external regression suite covers 4 repositories, 22 complete pinned source files, and 11 fixed tasks across Axios, Chalk, node-fetch, and Preact. The suite passes its repository gates, but its checked-in grading annotations are visible to implementation authors and are not a genuinely blinded benchmark.

The #924 protocol supplies the machinery for a real held-out run. A genuinely blinded result still requires an independent evaluator to withhold the answer key, precommit it before selection, record the selection receipt before reveal, reveal the matching key afterward, and attest to that process.

## Publication boundary

Repository file `packages/mcp-server/release-candidate.json` is the machine-readable source of truth for candidate selection. While it records `state: selected-not-published` and `publicationAuthorized: false`:

- `packages/mcp-server/package.json` and `package-lock.json` remain on the actually published v0.2.0 line;
- Codex/Claude plugin manifests and marketplace metadata remain on v0.2.0;
- `plugins/solvelang/.mcp.json` continues to pin `@solvelang/mcp-server@0.2.0`;
- no v0.3.0 tag or GitHub Release should be created;
- `.github/workflows/npm-release.yml` must remain release-published-only and protected by the `npm-production` environment, the ownership variable, exact tag/version validation, package tests, packed-consumer smoke, and npm Trusted Publishing.

Release finalization is a later reviewed change that must update package/lock/runtime/plugin versions coherently and pass exact-head CI before an explicitly authorized publication action.

## Rollback

This candidate-selection change is repository metadata, CI validation, and documentation only. Rollback is a normal reviewed revert. No production or customer data rollback is involved.
