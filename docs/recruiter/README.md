## Truthfulness rules

Use only claims that can be supported by this repository. Do not imply:

- production scale that has not been measured,
- customers or revenue that are not documented,
- team leadership that did not occur,
- benchmark results that were not run,
- enterprise readiness, SLAs, or compliance certifications,
- a hosted production workflow runtime when the Rust CLI remains the canonical runtime.

The safest framing is: **built, designed, implemented, tested, documented, or prototyped**.

## What SolveLang demonstrates

SolveLang is useful in interviews because it spans several engineering layers:

- language design and runtime implementation in Rust,
- parser, AST, diagnostics, imports, runtime semantics, and safety policy,
- AI-assisted workflow concepts and provider integration,
- local-first workflow analysis and browser tooling,
- Next.js/TypeScript product surfaces,
- AWS SAM, Lambda, DynamoDB, IAM, Stripe, and API-key infrastructure,
- testing, CI/CD, failure analysis, and incident-aware operations,
- product positioning, developer experience, documentation, and consulting strategy.

The project should be presented as an early product and serious engineering portfolio, not as a mature automation platform.
