# Future Roadmap

This is a roadmap, not a claim that these capabilities exist today.

## Near term

- finish portfolio, demo, recruiter, business, and open-source readiness work
- strengthen deterministic workflow explanation and evidence exports
- expand validated examples and contributor onboarding
- improve static analysis around AI, side effects, approvals, and failure paths
- stabilize test-mode API authorization and usage infrastructure

## Evidence-led next capabilities

Only prioritize after repeated demand appears in consulting or user research:

- typed workflow interfaces
- explicit approval primitives
- provider-neutral AI declarations
- trace/evidence schema
- one external execution adapter
- reusable implementation templates
- CI validation/reporting tools

## Later platform work

Managed execution should require explicit readiness criteria covering:

- tenant isolation
- secret management
- authentication and authorization
- deployment environments
- logs and traces
- quotas and billing
- failure recovery
- incident response
- support operations
- security review
- cost controls

## Product decision rule

The next major feature should solve a repeated observed problem, not merely make the project look larger.

## Interview framing

A strong answer to "what would you build next?" is not "everything on this page." Instead:

1. identify the target user and repeated problem,
2. choose the smallest capability that proves value,
3. define the safety and operational boundary,
4. add reproducible validation,
5. then decide whether productization is justified.
